# Dependências de PRODUÇÃO, com versão fixada.
#
# Sem pin, cada `docker build` podia trazer uma minor diferente de FastAPI,
# SQLModel ou Pydantic e quebrar produção sem nenhuma mudança de código — e o
# Dependabot configurado para /backend não tinha o que atualizar, dando falsa
# sensação de cobertura. Ferramentas de teste/lint moram em requirements-dev.txt
# e NÃO vão para a imagem.
#
# Para atualizar: suba a versão aqui, REGENERE o lock (abaixo), rode a suíte
# contra SQLite E Postgres, e só então faça o merge.
#
# ATENÇÃO — este arquivo NÃO é o que a imagem instala. As diretas estão fixadas
# aqui, mas as transitivas não estavam em lugar nenhum, e dois `docker build` do
# mesmo commit podiam resolver `httpcore`/`cffi`/`typing-extensions` diferentes:
# o ambiente que passou nos testes não era o que ia para produção. O Dockerfile
# instala `requirements.lock`, e o CI falha se ele divergir daqui.
#
# O lock é resolvido para LINUX/CPython 3.12 — a plataforma da imagem. Ele traz
# pacotes que não existem no Windows (`uvloop`, via `uvicorn[standard]`), então
# no desenvolvimento local em Windows continue instalando `requirements.txt` +
# `requirements-dev.txt`. Para regenerar, use o mesmo Python da imagem:
#
#   docker run --rm -v "$PWD:/src" -w /src python:3.12-slim \
#     sh -c "pip install pip-tools && pip-compile --output-file=requirements.lock --strip-extras requirements.txt"

# --- Segurança ---
# PyJWT no lugar de python-jose: o jose está praticamente sem manutenção e
# acumula CVEs (confusão de algoritmo, "JWT bomb"). PyJWT é mantido e exige
# `algorithms=` explícito na verificação.
PyJWT[crypto]==2.13.0
# Piso da `cryptography`, que entra pelo extra `[crypto]` acima e não tinha
# restrição própria: o resolvedor congelou a 49.0.0 e o `pip-audit --strict` do
# CI passou a reprovar por PYSEC-2026-3552 (oracle Bleichenbacher na
# descriptografia PKCS#7, corrigida na 50.0.0), bloqueando qualquer release.
# Este app não usa as APIs PKCS#7 e assina JWT só com HS256, então a
# explorabilidade aqui é baixa — o que não é motivo para carregar a versão
# vulnerável, e sim a razão de isto ser um piso e não um pin exato.
cryptography>=50.0.0
# argon2 é o algoritmo primário de senha (ver app/core/security.py). passlib
# segue apenas para VERIFICAR hashes antigos (pbkdf2_sha256/bcrypt) e permitir o
# rehash transparente no login; sai daqui quando não houver mais hash legado.
argon2-cffi==25.1.0
passlib==1.7.4
bcrypt==5.0.0

# --- Infra ---
httpx==0.28.1
structlog==25.5.0
anyio==4.13.0
python-dotenv==1.2.2
# Base de fusos para `zoneinfo`. O calendário do app é `APP_TIMEZONE`
# (America/Sao_Paulo por padrão) e o Windows não tem base de fusos do sistema —

tzdata==2026.3
